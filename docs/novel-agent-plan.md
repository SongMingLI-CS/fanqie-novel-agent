# 小说自动创作智能体实施计划

## 审计结论

2026-09-02 审计时仓库只有空的 Git 元数据：当前分支为 `master`，没有提交、工作树没有用户改动，也没有 `package.json`、README、AGENTS.md、数据库 schema、API 或部署配置。因此不存在可复用的框架、包管理器、数据库或部署平台；本项目从零建立服务端、Worker、SQLite 持久化和最小 Web 控制台。实现会把供应商与发布平台都放在服务端适配器之后，避免把运行时职责交给 Codex。

## 基线技术决策

- Node.js 20+、TypeScript、Fastify：轻量 HTTP 服务与类型安全。
- SQLite（`better-sqlite3`）作为默认单机持久化；schema 采用追加式迁移，保留未来替换数据库的 repository 边界。
- 独立 Worker 进程轮询数据库任务；锁、租约、幂等键和可恢复状态都由数据库约束保障。
- 前端使用服务端渲染的最小静态控制台，只通过 `/api` 访问服务端。
- DeepSeek 通过 OpenAI-compatible HTTP 客户端接入，默认模型为 `deepseek-reasoner`，地址和模型均由环境变量提供。
- 默认发布器为 `DryRunPublisher`；`LocalFilePublisher` 用于人工导出，外部平台只提供接口。

## Phase 顺序与验收证据

1. 审计、Skill、剧情状态模型：本文档、数据模型、Skill 文件、状态迁移单测。
2. DeepSeek 服务端客户端：超时、退避、结构化用量日志与密钥隔离测试。
3. 规划与生成：上下文裁剪、beat sheet、结构化章节输出和草稿服务。
4. 数据库、Job 状态机、Worker：租约、恢复、取消、重试、暂停与继续。
5. Reviewer：质量、一致性、重复、伏笔与发布阻断检查。
6. 草稿与控制台：列表、编辑、状态、审查、批准、暂停/继续、用量。
7. Dry-run、人工审核、导出流程。
8. ExternalPublisher 接口及配置边界，不接入未授权平台。
9. 全量测试、安全审计与生产构建。
10. 部署、运维、恢复和最终验收文档。

每个 Phase 必须有独立提交，progress 文档记录实际测试结果、风险和未完成项。失败测试必须标注是本次引入、原有问题（本仓库目前没有既有测试）还是外部服务缺失。

## 关键不变量

- `UNIQUE(novel_id, chapter_number)` 防止章节编号重复。
- 一个章节只能有一个活动生成任务；生成和导出分别使用稳定幂等键。
- 未通过审查或存在 `blockingIssues` 的章节不能批准或发布。
- 章节正文先保存为草稿；一致性检查通过后才提出 `proposed-story-state`，事务确认后才更新 StoryBible 当前状态。
- 自动发布必须同时满足环境开关、人工审核策略、平台配置、章节完整性和幂等检查。
- API 永不返回密钥、完整内部异常堆栈或未授权的全文上下文。

## 风险与待配置事项

- 本仓库尚无正式外部发布平台 API 和凭据；Phase 8 只交付接口与安全失败路径。
- SQLite 适合单机/小规模 Worker；多实例部署前需切换到支持行锁的数据库并保留 repository 契约。
- DeepSeek 的实际可用模型名、上下文窗口和 JSON 输出能力需由部署环境验证，不能在代码中伪造成功。
